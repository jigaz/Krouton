- **15 were caught.**

## 2. Contract Gaps That Block Any Rust Node (decide these first)

Rust parity with the *documented* contract is done. But the contract, as written, can't run an end-to-end burn. These four decisions are yours, and the Swift client changes with them.

**D1. The Swift client doesn't speak KRSP at all.** `SpoolRemoteNodeClient.swift` uses HTTP/JSON (`/api/v1/drives`, `/rack`, `/spool/calibrate`, `/bake`) over plain `http://`, plus `ws://…/api/v1/spool/events` for telemetry. All of the KRSP code (frames, manifest, pipeline, leases, pairing) is verified, but production never calls it. The audit's Suite 28 ratchet lists it as pending integration.

*Recommendation:* Rust spoold implements **KRSP only**. Don't build a second HTTP server to match the legacy client. Wire `SpoolUploadSender` into a `SpoolPeerSession` on the Swift side, then retire the HTTP client.

**D2. Kinds 7 (telemetry) and 8 (control) have no payload schema.** Leases, drive inventory, job submission, tray, calibration and telemetry have no defined bytes, so two independent implementations can't interoperate.

*Recommendation:*
- Put **JSON inside KRSP control frames** (≤ 64 KiB, field names in `snake_case` like the existing Codable models, plus a `"type"` tag).
- It's debuggable, Codable and `serde` make parity easy, and control traffic is tiny.
- Keep binary frames for extents only.
- Add the message set to the contract, with golden vectors for each message.

**D3. The node never receives the manifest's leaf digests.** `bitmapQuery` carries only the Merkle root, and the receiver needs `manifest.leafDigests[index]` to verify each extent. So a node has no way to accept an extent today.

*Recommendation:* **kind 10 `manifestOffer`**, which is implemented and tested in `spoold-proto` (`ManifestOffer`):
- `extentIndex` = sectors per extent
- `firstLBA` = total sectors
- `sectorSize` = sector size
- `digest` = root
- payload = the concatenated leaves (up to 262,144 leaves, which is 1 TiB at 4 MiB extents)

The node re-derives the root and refuses any mismatch. Swift needs one new case and about 20 lines.

**D4. In mTLS mode, the P-256 pin has no authenticated source.**
- `SpoolTLS.mutualTLSParameters` pins `SHA256(X9.63 P-256 key)`, but pairing exchanges only Ed25519 and X25519 keys.
- Nothing authenticated ever carries the TLS key, so the pin would have to be trusted on first use (TOFU), the weakest option.

*Recommendation:* **pairing v2** appends the 65-byte X9.63 TLS public key to the hello (80 → 145 bytes), with the labels bumped to `…-v2`.
- The 6-digit code then authenticates the TLS key as well.
- Node IDs stay Ed25519-based and unchanged.
- The Ed25519 session proof over the TLS exporter stays as a second, independent identity check.

*Alternative:* make P-256 the only identity key. That's simpler long term, but every node ID changes.

## 3. Security Findings

| # | Severity | Finding | Fix |
|---|---|---|---|
| S1 | High | D1/D4 above: plain HTTP today, and mTLS pins with no authenticated source | As above |
| S2 | High (future) | **The classic rustls mistake to avoid in milestone 2:** a custom `ClientCertVerifier` that compares the pin and returns success *without* verifying the TLS 1.3 handshake signature authenticates nothing, because anyone can present someone else's public certificate. | Pin check *plus* `verify_tls13_signature` from the crypto provider. Add a negative test: a handshake replaying a pinned certificate without its key must fail. |
| S3 | Medium | The HMAC envelope's signed message is `timestamp.nonce.payload`, with no method or path, so a captured signature can be replayed against a different endpoint within 30 s. `seenNonces` grows without bound. The secret is a `String`, so it's likely low-entropy. | Retire the envelope with the HTTP client. Until then, sign `METHOD path ts nonce payload` and prune nonces older than the skew window. |
| S4 | Medium | X25519 low-order points: the Rust crate rejects non-contributory shared secrets (tested). CryptoKit's behaviour should be pinned too. | Add a Swift check that an all-zero peer ephemeral key fails `complete`. |
| S5 | Low | **Correction:** in my questions I said the PSK path forces TLS 1.3 while offering a TLS 1.2-only cipher suite. The TLS 1.3 minimum is set only on the mTLS path, so PSK negotiates TLS 1.2 PSK, without forward secrecy. Moot now that you've chosen mTLS. | Delete the PSK path once mTLS works end to end. |
| S6 | Info | Exporter parity: Swift's `sec_protocol_metadata_create_secret` and rustls's `export_keying_material(label, context: None)` agree **only under TLS 1.3**, where an absent context equals an empty one. | Keep TLS 1.3 as the minimum on both sides. |
| S7 | Info | The Rust endpoint parser relies on `std::net`, which already refuses `010.0.0.1`, and the same 17 host cases as Swift Suite 27 pass. | — |

## 4. Bugs & Code Quality in the Swift Reference

1. **The synthesis step stripped the explanatory comments** from the reference files. The cutover lead-formula derivation, the lease state diagram, the commitment rationale and the journal ordering notes are all gone. Those comments are the spec. Restore them: Rust and Swift must implement the same *reasons*, not just the same bytes.
2. **Stricter ack guard:** the Swift sender now ignores acks for extents not in flight. That's correct, Rust matches it, and it's now tested in both directions (§1).
3. **Sector sizes 2336 and 2448** were added on Swift. Rust accepts them, and S2 checks all four sizes plus a refused 2340.
4. **armv7:** Swift only runs on 64-bit Apple hardware, but Rust will run on a 32-bit Pi. All Rust byte offsets are `u64`, and clippy denies truncating casts (S3 checks exact BD-50 offsets).

## 5. Test Strategy Going Forward

- **One gate:** `krouton-spoold-verify` must print `0 failed; second run identical: yes`, and CI runs it on every OS in the matrix.
- **Cross-language parity:** new protocol behaviour starts as a vector in `tools/gen_golden_vectors.py`; then Rust and Swift both implement it until they pass. CI regenerates the vectors and diffs them, so the file can't be hand-edited.
- **Mutation spot checks:** for each new rule, break it once and confirm the harness catches it. The script I used is easy to keep.
- **Next additions:**
  - `cargo-fuzz` targets for `FrameDecoder`, `ManifestOffer::decode`, `ExtentBitmap::from_wire` and `TxtHints::parse`.
  - A rustls handshake test with an in-memory pipe for S2.
  - Golden vectors for every D2 control message.
