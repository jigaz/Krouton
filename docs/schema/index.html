File formats

Krouton writes files that should still make sense in twenty years, with or without Krouton. This page lists them, each described as a JSON Schema so any program can check and read them.

On the disc

Disc set index
krouton-set-index.json, at the root of every disc in a set Krouton spans across several discs. It lists every file on every disc with its size and SHA-256, so any one disc tells you which disc to fetch for a file. It sits beside standard BagIt files (RFC 8493), which any archive's tools can check without Krouton.

On your Mac

Project file (.krut)
A saved project: the files to burn, where they go, track order and the label. It refers to your files where they are rather than copying them.

On the web

Depot feed
The list of disc images at depot.krouton.app, which Krouton's Disc Image Depot reads from depot.krouton.app/v1/manifest.json. Each image has its download address, size and checksum.
Drive report
One burn on one drive: the drive, its connection, the disc and how it went. Reports are collected openly in the optical disc archive.

Between the app and Krouton Server

The network protocol (KRSP v1) and the folder bundles it carries are described in the Krouton Server documentation. They are pinned by test vectors in Vectors/, which both the app and the server must reproduce byte for byte.

How versions work

Every format has a version in its address, such as /v1.json, and a published version never changes in a way that breaks readers. New optional fields may be added to a version, and readers ignore fields they don't know. Anything else, such as removing a field or changing what one means, becomes a new version at a new address, and the old one stays published.
